# v0.0.8 版本归档

v0.0.8 补全 Google OAuth 账号导入对 Cursor 真实网页身份响应的兼容。Python、Web、桌面及随包后台统一为 `0.0.8`；API 主版本保持 `1`，数据库 schema 保持 `0004_retention`。

## 更新内容

- **兼容网页身份的裸 ID**：Google OAuth Cookie 的 JWT subject 为 `google-oauth2|user_…`，但 Cursor 网页 `me` 接口可能返回同一账号的裸 `user_…`。身份资料校验现在允许这组对应关系，修复 `v0.0.7` 仍会在网页身份验证阶段误报服务请求失败的问题。
- **保留完整提供方身份**：兼容仅作用于 Cursor 返回的身份资料。网页与桌面 JWT、桌面 `authId` 和数据库继续保留完整 OAuth subject；不同用户 ID、错误邮箱及两个显式不同的提供方仍被拒绝。
- **按真实响应修正测试**：模拟网关现在与实测一致，网页 `me` 返回裸 `sub`，桌面 `GetMe` 返回带提供方的完整 `authId`。新增随包后台的 OAuth 添加与重新授权回归，避免源码测试通过但安装包仍失败。

## 实际验证

经用户明确授权，使用其 Google OAuth Cookie 在临时数据库与内存密钥组成的隔离 Core 中执行一次完整导入。网页身份查询、桌面 callback/poll、桌面身份查询和 6 个额度接口全部返回 200，签发桌面 Token 的 subject 与网页 JWT 一致，账号及额度快照成功保存。诊断日志不包含邮箱、用户 ID 或 Token，临时数据库随后删除；测试未操作用户已安装面板的数据或本机 Cursor。

本地修复版客户端已完成冻结后台测试、OAuth 随包导入/重新授权、签名完整性、冷/热启动、异常退出清理和实际安装替换验证。Python 回归 374 项中 364 通过，10 项因本机缺少 PowerShell 跳过；Web 和独立桌面浏览器流程通过。

- 已安装 `v0.0.7` 的客户端可在“关于与更新”检查并安装 `v0.0.8`，或完全退出后使用完整安装包覆盖升级。
- 本次不改变应用标识、数据目录、系统凭证库、更新签名密钥及数据库 schema，已有账号、快照、连接和显示偏好保持不变。
- 本次真实验证仅确认所提供 Google 账号的导入链路，不代表 GitHub OAuth、原生切换或多设备会话已经完成真实上游验证。
