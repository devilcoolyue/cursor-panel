# v0.0.9 版本归档

v0.0.9 修正同名 Cursor Pro 套餐存在多种 Other Models 容量时的额度上限推算。Python、Web、桌面及随包后台统一为 `0.0.9`；API 主版本保持 `1`，数据库 schema 保持 `0004_retention`。

## 更新内容

- **区分不同额度容量**：同名 Pro 套餐可能同时存在 `$450 / $45 / $495` 和 `$450 / $22.50 / $472.50`。跨账号补齐现在同时核对套餐信息、重叠账期及本账号已知上限，避免 Other Models 已用尽后错误显示另一档容量。
- **保留本账号同账期上限**：本次用量因触顶或百分比过近而无法完整反推时，优先沿用本账号同套餐、同账期且不冲突的历史结果。换套餐、换账期或出现新的直接观测后自动停止沿用。
- **明确标记耗尽后的估算**：三档均已耗尽、未使用按量付费且累计消费接近唯一已观测容量时，可以辅助匹配对应额度档位，页面以 `≈` 标记并说明它不是官方确认值。估算结果不会成为其他账号的新观测。
- **容量不明确时保留空值**：零消费账号只能确认各容量共同一致的档位；Other Models 同时存在 `$22.50` 和 `$45` 时不会按账号数量猜测，也不会生成两档之间并不存在的平均额度。
- **加强一致性与权限边界**：补齐后的两个分池必须与综合池相符。V2 只使用当前用户可见账号的观测；手工参考值、跨账号估算和耗尽估算都不会继续向其他账号传播。

## 实际验证

经用户授权，对 69 个生产账号的额度快照进行只读分析，并对反馈账号读取当前周期用量。完整观测确认两种容量同时存在；反馈的 `$472.50` 综合池账号恢复为 `$450 / $22.50 / $472.50`，原有 `$495` 综合池账号继续保持 `$450 / $45 / $495`。两份已耗尽样本的模型明细分别显示 Cursor / Other 消费约为 `$450.61 / $45.54` 和 `$450.35 / $45.98`，支持将其匹配到 `$450 / $45 / $495` 档位，同时保留近似语义。

修复在 69 个脱敏快照上完成纯计算回放；本地 Python 完整回归 392 项中 382 项通过，10 项因缺少 PowerShell 跳过。前端生产构建、真实 Chrome 浏览器流程、API 契约生成、Python 静态检查及发行一致性检查通过。生产数据只用于只读核对和脱敏回放，不包含在发布包中。

## 安装与升级

[GitHub Release v0.0.9](https://github.com/devilcoolyue/cursor-panel/releases/tag/v0.0.9) 提供 macOS Apple Silicon / Intel、Windows x64、Linux amd64 服务端、Python wheel、源码、校验文件和签名更新产物。

- 已安装 `v0.0.8` 的客户端可在“关于与更新”检查并安装 `v0.0.9`，或完全退出后使用完整安装包覆盖升级。
- 本次不改变应用标识、数据目录、系统凭证库、更新签名密钥及数据库 schema，已有账号、凭证、连接和显示偏好保持不变。
- 美元上限仍是根据 Cursor 非公开接口数据得到的推算或估算；剩余百分比始终沿用 Cursor 返回口径。带 `≈` 的额度表示耗尽消费辅助估算，不应视为官方账单承诺。
