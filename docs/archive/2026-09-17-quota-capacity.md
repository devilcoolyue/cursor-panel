# 新旧额度容量混用修正

日期：2026-09-17。分支：`fix/quota-capacity-cohorts`。

## 现象与依据

经用户授权，只读检查生产 69 个账号的额度快照，并对反馈涉及的 4 个账号读取当前周期用量。未修改生产服务、数据库或凭证；以下仅记录不含身份与授权材料的额度统计。

当前可完整反解的快照中，16 个为 `$450 / $45 / $495`，13 个为 `$450 / $22.50 / $472.50`。同名 Pro 套餐同时存在不同容量，不能将 Other Models 统一写成 `$22.50`，也不能按全部 Pro 账号的中位数补齐。

旧逻辑在分池已用百分比达到 100%，或分池与综合百分比差小于 0.05 个百分点时，只保留综合池估算，再从同名套餐借用缺失的分池容量，导致出现 `$450 + $45` 与 `$472.50` 并列的矛盾。

两份耗尽样本的 Other Models 消费由总消费减去 Cursor Models 消费得到约 `$22.52` 和 `$24.32`，接口均返回 100%。因此仍需保留触顶保护，不能假设 100% 就是恰好用尽额度。另一份样本的比例十分接近，原始反解保护同样有效。

## 修正行为

- 优先当前反解，其次本账号同套餐、同账期且与当前容量相符的历史上限。Legacy 也将自身历史保留到成功快照中，刷新及重启后继续可用。
- 跨账号补齐先匹配套餐信息、重叠账期和已有上限；综合池 `$472.50` 不借用 `$495` 的分池容量。V2 保持仅使用当前授权查询可见账号的边界。
- 允许小幅取整误差，同容量内使用过半观测支持的中位数，并检查分池之和与综合池一致。容量无法区分时，不按多数投票选档，也不把不同档位平均成不存在的容量。
- 刷新替换旧观测，删除账号清理观测，启动重新建立观测集合。跨账号估算和手动参考值不作为自身观测继续传播。

## 验证

69 个生产快照的脱敏额度字段在本地纯计算回放：4 个反馈账号均得到 `$450 / $22.50 / $472.50`；19 个账号保留或补齐 `$450 / $45 / $495`，18 个得到 `$450 / $22.50 / $472.50`。其余 32 个账号无法区分所属容量，只显示共同有依据的 Cursor Models `$450`，Other Models 和综合池美元上限留空，剩余百分比不变。

针对额度匹配、历史保存、快照与持久化的 88 项测试通过。新增覆盖耗尽、近似退化、低用量、新旧容量共存、容量歧义、取整误差、套餐/账期隔离、矛盾历史、删除与重启清理。

完整回归共 385 项：375 项通过，10 项因本机缺少 PowerShell 跳过，无失败，耗时 85.506 秒。前端 TypeScript/生产构建、发行一致性检查、相关 Python 静态检查及 diff 空白检查通过。
