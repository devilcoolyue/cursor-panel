# Legacy 额度容量修正

日期：2026-09-17。分支：`legacy`。移植来源：`7805970`。

同名 Pro 套餐目前同时存在 `$450 / $45 / $495` 和 `$450 / $22.50 / $472.50` 两种容量。分池触顶或百分比接近时，旧逻辑从全部同名套餐取中位数，可能把 Other Models 的 `$22.50` 补成 `$45`，同时仍显示综合 `$472.50`。

本次移植包含容量匹配、同账期自身历史保存、观测清理及相关测试，不依赖 V2 的领域模块或数据库。上限优先使用当前反解，其次本账号同账期历史；跨账号补齐须满足相同套餐信息、重叠账期和已知容量约束。容量有歧义时金额留空，剩余百分比仍沿用上游。分池触顶和退化保护保持有效，不写死套餐金额。

## 验证

- Legacy 完整回归 199 项：190 项通过，9 项因本机缺少 PowerShell 跳过，无失败。
- Python 相关文件 Ruff E4/E7/E9/F、四个前端入口的 JavaScript 语法检查、diff 空白检查通过。
- 回归包含耗尽后上限稳定、近似退化、新旧容量共存、矛盾历史、账期和套餐变化、删除清理及重启持久化。
- 此前经用户授权核对的 69 个生产快照中，反馈的 4 个账号对应 `$450 / $22.50 / $472.50`。另外 32 个快照不足以区分容量，修复后相应美元金额留空，不改百分比。

## 服务端更新

Legacy 使用 [现有 systemd 部署流程](../operations.md)，按 Git 提交标识此次修复，不使用新版桌面发行流水线。发布前通过 SQLite 在线备份 API 生成包含 WAL 已提交数据的完整备份并检查完整性，同时保留旧源码提交。服务器切换到跟踪 `origin/legacy` 的本地 `legacy` 分支，锁定依赖同步后重启。

上线核验包括服务 active、网页与只读账号 API 正常、账号数量及数据库完整性、反馈账号的三档额度、后台调度运行及错误状态。数据库 schema 和依赖锁不变；若启动或核验失败，可切回部署前提交并恢复服务。
