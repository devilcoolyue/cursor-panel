# v0.0.10 版本归档

v0.0.10 适配 Cursor 网页登录回调新增的 CSRF 校验，修复添加或重新授权账号时提示“服务请求失败”的问题。Python、Web、桌面及随包后台统一为 `0.0.10`；API 主版本保持 `1`，数据库 schema 保持 `0004_retention`。

## 更新内容

- **适配登录回调 CSRF 校验**：Cursor 现在要求 `POST /api/auth/loginDeepCallbackControl` 携带双提交 CSRF token，缺少时返回 `403 {"error":"Invalid CSRF token"}`。该响应原先被归为会话失效，桌面客户端显示“服务请求失败”，旧网页面板提示 Cookie 失效。申请桌面授权前现在会在同一会话内获取 `/api/csrf-token`，以同值的 `csrf-token` Cookie 与 `x-csrf-token` 请求头提交，与 Cursor 网页行为一致。
- **同步真实会话实验脚本**：`dev/verify-session-lifecycle.py` 的网页 POST 请求采用相同的 CSRF 处理。
- **其余接口不变**：网页身份查询、桌面 poll、续期及 6 项桌面额度接口的上游行为未发生变化，已保存账号的常规刷新和切换不受影响。

## 实际验证

使用不带任何 Cookie 或 Token 的匿名请求逐项探测添加账号链路：仅登录回调新增 CSRF 校验，其余接口状态码与既有分类一致。使用修复后的客户端代码匿名调用回调时，CSRF 校验通过并返回未登录的 WorkOS 跳转；旧逻辑仍为 403。本次未使用真实账号凭证执行完整导入。Cursor 网页同时在回调中提交 Castle 风控 token，客户端无法生成该值；若上游开始强制校验，仍需另行适配。

单元测试覆盖 token 获取、请求头与 Cookie 一致性，以及缺少 token 时不发送回调。

## 安装与升级

[GitHub Release v0.0.10](https://github.com/devilcoolyue/cursor-panel/releases/tag/v0.0.10) 提供 macOS Apple Silicon / Intel、Windows x64、Linux amd64 服务端、Python wheel、源码、校验文件和签名更新产物。

- 已安装 `v0.0.9` 的客户端可在“关于与更新”检查并安装 `v0.0.10`，或完全退出后使用完整安装包覆盖升级。
- 本次不改变应用标识、数据目录、系统凭证库、更新签名密钥及数据库 schema，已有账号、凭证、连接和显示偏好保持不变。
