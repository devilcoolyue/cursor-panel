# v0.0.7 版本归档

v0.0.7 修复 OAuth 账号导入与更新说明显示问题。Python、Web、桌面及随包后台统一为 `0.0.7`；API 主版本保持 `1`，数据库 schema 保持 `0004_retention`。

## 更新内容

- **OAuth Cookie 导入**：`WorkosCursorSessionToken` 的 JWT subject 现在支持裸 `user_…` 以及单层身份提供方前缀，包括 `auth0|`、`google-oauth2|` 和 `github|`。Cookie 中的账号 ID 通过后，仍保留完整 subject 用于网页身份、桌面凭证、持久化和续期校验；不同提供方不会因用户 ID 后缀相同而被视为同一身份。修复 [Issue #2](https://github.com/devilcoolyue/cursor-panel/issues/2)。
- **准确的 Cookie 错误提示**：格式错误、已过期或账号不匹配的 Cookie 在添加及重新授权时返回明确的 422 错误，客户端显示对应处理建议，不再误报为网络失败。上游网络或桌面凭证故障继续使用脱敏的服务错误提示。
- **更新说明 Markdown 渲染**：“关于与更新”会将 GitHub Release 正文渲染为标题、列表、强调、链接、引用、表格和代码块，并保持桌面、Web、明暗模式及窄屏下的可读层级。原始 HTML 不执行，远程图片转为显式链接，外链在新窗口打开。
- **发布依赖与许可**：加入固定版本的 `markdown-it` 解析器，浏览器生产依赖审计无已知漏洞；解析器及实际进入浏览器包的依赖许可随前端资源发布。

## 安装与升级

[GitHub Release v0.0.7](https://github.com/devilcoolyue/cursor-panel/releases/tag/v0.0.7) 提供 macOS Apple Silicon / Intel、Windows x64、Linux amd64 服务端、Python wheel、源码、校验文件和签名更新产物。

- 已安装客户端可在“关于与更新”检查并安装，或完全退出后使用完整安装包覆盖升级。
- 本次不改变应用标识、数据目录、系统凭证库、更新签名密钥及数据库 schema，已有账号、快照、连接和显示偏好保持不变。
- 修复使用合成 Cookie、临时数据库和模拟 Cursor 网关覆盖 Google/GitHub 格式的导入、重新授权、续期及身份不匹配；未使用真实凭证，也未扩大真实上游会话的验证声明。

## 验证

本地回归覆盖 OAuth subject 解析、错误 Cookie 在出站请求前被拒绝、完整身份保持、重新授权与强制续期、Web/独立桌面错误提示，以及 Markdown 的标题、列表、强调、代码、链接、原始 HTML 和远程图片边界。前端生产构建、桌面与 Web 截图检查、依赖审计、API 契约和源文件检查通过。

固定发布流程还会在发布前执行完整后端回归、三种桌面架构的浏览器与系统验证、安装后启动检查、Linux 镜像与 wheel 验证、更新签名及全部附件校验。
